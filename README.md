# 淘宝用户行为数据分析

一个面向数据分析实习求职的完整项目，围绕“数据采集 -> 数据清洗 -> 数据存储 -> 可视化分析 -> 业务洞察”构建了完整闭环。

---

## 项目简介

传统数据分析项目往往只停留在“跑通代码”或“画出图表”，而这个项目进一步把分析结果与业务决策挂钩：

- 从 Kaggle/天池 获取淘宝用户行为公开数据集（约 1 亿条原始记录）
- 使用 Python（Pandas）进行数据清洗与预处理，解决时间戳格式错误、数据抽样等真实问题
- 设计 MySQL 数据库表结构，将清洗后的数据落地存储
- 基于 Power BI 构建交互式看板，直观呈现用户行为分布与转化漏斗
- 输出结构化业务洞察，帮助理解用户从浏览到购买的流失节点

这个项目不是“跟着教程敲一遍”，而是一个包含数据获取、数据清洗、数据建模、可视化分析、业务洞察、文档输出的完整数据分析项目。

---

## 核心亮点

### 1. 面向真实业务的完整闭环

项目实现了从原始数据到业务决策的完整链路：

- 原始数据获取与抽样策略设计
- 数据清洗与质量校验
- 数据库表结构设计与数据导入
- 可视化看板搭建
- 业务洞察输出与运营建议

### 2. 解决真实数据问题

项目中遇到了多个真实场景下的数据问题并逐一解决：

- **时间戳格式错误**：1 亿行数据中 10 位秒级时间戳误用 unit='ms' 导致日期显示为 1970 年，修复后恢复为 2017 年 11 月正确日期
- **数据抽样策略**：前 20 万行仅覆盖 1 天，改用 60 万行后覆盖 5 天连续趋势，使折线图呈现真实波动
- **本地 Python 环境冲突**：同时存在 Python 3.8 和 3.14，通过指定完整路径解决库依赖问题
- **Power BI 连接 MySQL**：通过安装 MySQL Connector/Net 驱动打通数据链路

## 数据说明

- **数据来源**：淘宝用户行为公开数据集（Kaggle / 阿里云天池）
- **原始规模**：约 1 亿条
- **抽样规模**：60 万行（覆盖 5 天连续趋势）
- **时间范围**：2017 年 11 月 25 日 ～ 2017 年 11 月 29 日

### 字段说明

| 字段名 | 含义 | 示例 |
| :--- | :--- | :--- |
| user_id | 用户唯一标识 | 1 |
| item_id | 商品唯一标识 | 2268318 |
| category_id | 商品类目 ID | 2520377 |
| behavior_type | 行为类型（pv/fav/cart/buy） | pv |
| timestamp | 行为发生时间（10位秒级时间戳） | 1511544070 |

## 分析结论

| 行为类型 | 数量 | 占比 |
| :--- | :--- | :--- |
| 浏览（pv） | ~538,830 | 89.8% |
| 加购（cart） | ~32,950 | 5.5% |
| 收藏（fav） | ~12,210 | 2.0% |
| 购买（buy） | ~16,000 | 2.7% |

### 转化漏斗

| 转化路径 | 转化率 |
| :--- | :--- |
| 浏览 → 购买 | 2.4% |
| 加购 → 购买 | 39.7% |

### 核心洞察

1. **加购环节流失最严重**：60.3% 的用户加购后未完成购买
2. **整体购买转化率偏低**：2.4% 的浏览→购买转化率处于行业中等偏低水平
3. **收藏行为占比小**：仅 2.0%，用户更倾向于直接加购
