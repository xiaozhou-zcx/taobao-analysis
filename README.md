淘宝用户行为数据分析
一个面向数据分析实习求职的完整项目，围绕“数据采集 -> 数据清洗 -> 数据存储 -> 可视化分析 -> 业务洞察”构建了完整闭环，重点体现了我在 Python数据处理、MySQL数据库管理、Power BI可视化、业务分析思维 方面的能力。

📌 项目简介
传统数据分析项目往往只停留在“跑通代码”或“画出图表”，而这个项目进一步把分析结果与业务决策挂钩：

从 Kaggle/天池 获取淘宝用户行为公开数据集（约 1 亿条原始记录）

使用 Python（Pandas）进行数据清洗与预处理，解决时间戳格式错误、数据抽样等真实问题

设计 MySQL 数据库表结构，将清洗后的数据落地存储

基于 Power BI 构建交互式看板，直观呈现用户行为分布与转化漏斗

输出结构化业务洞察，帮助理解用户从浏览到购买的流失节点

这个项目不是“跟着教程敲一遍”，而是一个包含 数据获取、数据清洗、数据库设计、可视化分析、业务洞察、文档输出 的完整数据分析项目。

2. 解决真实数据问题
项目中遇到了多个真实场景下的数据问题并逐一解决：

时间戳格式错误：1 亿行数据中 10 位秒级时间戳误用 unit='ms' 导致日期显示为 1970 年，修复后恢复为 2017 年 11 月正确日期

数据抽样策略：前 20 万行仅覆盖 1 天，改用 60 万行后覆盖 5 天连续趋势，使折线图呈现真实波动

本地 Python 环境冲突：同时存在 Python 3.8 和 3.14，通过指定完整路径解决库依赖问题

Power BI 连接 MySQL：通过安装 MySQL Connector/Net 驱动打通数据链路

3. 转化漏斗分析（核心业务价值）
不同于只做“描述性统计”，本项目重点分析了用户从浏览到购买的转化漏斗：

转化路径	转化率	行业参考
浏览 → 购买	2.4%	电商行业平均 1%-3%
加购 → 购买	39.7%	加购后流失严重
核心洞察：60.3% 的用户加购后未完成购买，加购环节是最大的流失点。

4. 看板设计体现业务思维
Power BI 看板不是图表的简单堆砌，而是围绕业务问题组织：

总用户数：整体流量规模

各行为类型数量分布：用户行为集中在哪个环节

行为类型占比：直观展示浏览、加购、收藏、购买的比例关系

每日用户活跃趋势：时间维度上的波动，可识别峰值与低谷

📈 分析结论
各行为类型数量分布
行为类型	数量	占比
浏览（pv）	~538,830	89.8%
加购（cart）	~32,950	5.5%
收藏（fav）	~12,210	2.0%
购买（buy）	~16,000	2.7%
转化漏斗
转化路径	计算方式	转化率
浏览 → 购买	buy / pv	2.4%
浏览 → 加购	cart / pv	6.1%
加购 → 购买	buy / cart	39.7%
浏览 → 收藏	fav / pv	2.3%
核心洞察
加购环节流失最严重：60.3% 的用户加购后未完成购买，购物车页面存在明显优化空间

整体购买转化率偏低：2.4% 的浏览→购买转化率处于行业中等偏低水平

收藏行为占比小：仅 2.0%，用户更倾向于直接加购而非收藏，可能与促销活动或用户习惯有关

11 月 25 日活跃度最高：双十二预热期用户活跃度显著上升

运营建议
建议	预期效果
优化购物车页面：简化结算流程，减少加购后流失	预计提升加购→购买转化率 5-10%
加购后触达提醒：通过优惠券或库存紧张提示促进转化	预计提升购买转化率 3-5%
针对高活跃用户定向推送：11 月 25 日前后加大促销力度	预计提升整体 GMV
优化商品详情页：提升浏览→加购的转化效率	预计提升加购率 2-3%
